# Telnyx telephony adapter (C7)

`internal/adapters/telephony/telnyx` is the **second** `ports.Telephony` adapter. It proves
DESIGN.md §1.2 ("swap any provider at any time") on the telephony port: the core cannot
tell Twilio from Telnyx because both normalize everything to `domain.CallEvent` plus
canonical PCM16 audio.

It uses Telnyx **Call Control** (REST + call-control webhooks) and **bidirectional Media
Streams** (the adapter is the WebSocket server; Telnyx is the client). No Twilio code or
configuration is involved, and the adapter was built and tested **without a Telnyx account**:
every test drives in-repo fake HTTP/SSE/WebSocket servers.

## Selecting it

```bash
INSTEADLY_TELEPHONY_PROVIDER=telnyx
INSTEADLY_HTTP_PUBLIC_URL=https://<public-tunnel-host>   # https origin, no trailing slash
INSTEADLY_TELNYX_API_KEY=KEY_…                            # secret
INSTEADLY_TELNYX_CONNECTION_ID=<call-control-app-id>
INSTEADLY_TELNYX_FROM_NUMBER=+15551234567                 # E.164 caller ID you own
INSTEADLY_TELNYX_WEBHOOK_PUBLIC_KEY=<ed25519-public-key>  # optional; enables signature checks
INSTEADLY_TELNYX_RING_TIMEOUT_SECONDS=0                   # 0 = Telnyx default, else 5..600
```

`config.Validate` requires the API key, connection id, an E.164 `from` number, and
`http.public_url` when the provider is `telnyx`. The API key and the webhook public key are
never logged; `/healthz` reports only `telephony=telnyx`.

## Outbound call flow

1. `Dial` validates the clinic number (E.164), creates a `domain.CallID`, registers a
   session, and `POST /v2/calls` with `{to, from, connection_id, webhook_url, timeout_secs?}`.
   The response's `data.call_control_id` is the provider id for all later commands.
2. Telnyx posts call-control webhooks to `{public_url}/webhooks/telephony/telnyx/webhook/{callID}`:
   `call.initiated` → `dialing`, `call.answered` → `ringing`/`answered` (gaps synthesized),
   `call.hangup` → `ended` with a normalized `domain.EndReason`.
3. On `call.answered` the adapter calls
   `POST /v2/calls/{id}/actions/streaming_start` with:
   ```json
   {"stream_url":"wss://…/webhooks/telephony/telnyx/stream/<callID>",
    "stream_track":"both_tracks",
    "stream_bidirectional_mode":"rtp",
    "stream_bidirectional_codec":"PCMU"}
   ```
   The two bidirectional fields are required: Telnyx's default is a one-way mp3 stream.
4. Telnyx connects to the WebSocket. The adapter validates the `start` message
   (`stream_id`, `call_control_id`, `media_format` = `PCMU`/8000/1) and answers the runner's
   optional `StreamReady()` diagnostic.
5. Inbound 160-byte µ-law frames are decoded, upsampled 8→16 kHz, and delivered as
   640-byte canonical chunks (only the `inbound` track of `both_tracks`). Outbound canonical
   chunks are downsampled with an anti-alias filter, µ-law encoded, and written as
   `{"event":"media","media":{"payload":…}}`.
6. `{"event":"mark","mark":{"name":…}}` is echoed by Telnyx after all queued media played;
   the echo becomes `EventPlaybackMark`. `clear` maps to `ClearAudio`.
7. `Hangup` ends the session locally, then `POST /v2/calls/{id}/actions/hangup`; the
   documented `90018` ("call has already ended") response is treated as success.

## HTTP surface

Mounted by `httpapi` only when `telephony.provider=telnyx`:

| Route | Purpose |
|---|---|
| `POST /webhooks/telephony/telnyx/webhook/{callID}` | call-control events |
| `GET /webhooks/telephony/telnyx/stream/{callID}` | bidirectional media-stream WebSocket |

## Authentication

Telnyx signs webhooks with **Ed25519**, not HMAC. Each signed request carries:

- `telnyx-signature-ed25519` — base64 Ed25519 signature (hex is also accepted);
- `telnyx-timestamp` — Unix seconds.

The signed message is `{timestamp}|{raw body}` (for the WebSocket handshake:
`{timestamp}|{stream_url}`), and requests older/newer than five minutes are rejected. The
account public key is configured with `INSTEADLY_TELNYX_WEBHOOK_PUBLIC_KEY` (base64 raw
32-byte key or a PEM `PUBLIC KEY` block); a malformed key fails at startup.

Policy, per plan §5.2 but with the verified algorithm:

- signature headers **present** → they must verify; if no public key is configured the
  request is rejected (`403`), i.e. fail closed;
- signature headers **absent** → the capability check applies: the unguessable per-call
  path (32 lowercase hex chars generated by the core) plus a `call_control_id` match and,
  when the event carries it, a `connection_id` match against the configured app.

Unknown or already-finished calls are acknowledged with `200` so Telnyx stops retrying.
Unexpected inbound (`direction=incoming`) calls are hung up; this adapter dials outbound
calls only.

## DTMF

Inbound digits arrive as `{"event":"dtmf","dtmf":{"digit":…}}` and become `EventDTMF`.
Telnyx's media stream has no outbound DTMF message, but Call Control does:
`SendDTMF` posts `{"digits":"…"}` to
`POST /v2/calls/{id}/actions/send_dtmf`. The documented digit set is `0-9 A-D * #` plus
`w`/`W` pauses. Digits are only sent on an answered call.

## Audio codec

`telnyx/audio.go` is a self-contained G.711 µ-law ↔ PCM16 implementation with 8↔16 kHz
resampling (µ-law decode table, linear-interpolation upsample, anti-alias downsample). It is
a copy of the conversion proven in the Twilio adapter, not an import: adapters never import
each other and the core never depends on a codec.

## Testing

All tests run against in-repo servers and require **no account, key, or network**:

- fake REST API (`httptest`) asserting the Bearer header and the exact `POST /v2/calls`,
  `streaming_start`, `send_dtmf`, and `hangup` bodies;
- `httptest.NewServer(adapter.Handler())` plus a loopback `coder/websocket` client playing
  Telnyx (start/media/dtmf/mark/stop) and reading outbound media/mark/clear;
- webhook signature vectors (valid, tampered, stale, missing key) and capability checks;
- a full end-to-end fake call (dial → answered → stream → audio in/out → DTMF → mark →
  hangup).

`internal/app/swapability_test.go` additionally runs the real Telnyx adapter through the
real runner and agent against the fake REST/media-stream servers.

## Deviations from the plan (see plan §14)

- Webhook signatures are Ed25519 (`telnyx-signature-ed25519` + `telnyx-timestamp`), not
  HMAC-SHA256/`X-Telnyx-Signature`; an optional `INSTEADLY_TELNYX_WEBHOOK_PUBLIC_KEY` was
  added.
- Media-stream marks **are** supported by Telnyx and are implemented as provider echoes,
  not local marks.
- `streaming_start` sets `stream_bidirectional_mode=rtp` and
  `stream_bidirectional_codec=PCMU`; the plan's body omitted them.
